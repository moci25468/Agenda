# 青理课表助手 v1.0

青岛理工大学校园智能助手的最小可用版本：**每日定时拉取个人课表与考试 → 变更检测 → Bark / 邮件推送 → AI 课表问答**。
对应项目开题中「拟实现功能」的第一阶段落地实现。

## 功能

- **课表接入**：四种数据源可切换
  - `mock`：内置演示课表（开箱即用，页面明确标注「演示数据」）
  - `portal`：青岛理工融合门户（**一键登录自动获取**，或浏览器 Copy as cURL 导入；含登录态过期告警；课表变更最及时）
  - `zhengfang`：正方教务 jwglxt 适配器（账号密码登录或 Cookie 模式）
  - `httpjson`：通用 HTTP JSON 接口（配置 URL / 请求头 / 字段映射即可接入任意课表 API）
- **考试安排**：正方教务账号 / Cookie 模式下拉取考试（时间、考场、座号），独立快照与「考试」页；门户用户可只填正方凭证用于考试，课表仍以门户为准；演示源提供示例考试数据
- **一键登录门户**：用本机 Chrome 打开学校官方登录窗口，登录后自动发现课表接口、取会话 Cookie、写回配置并同步；不接触账号密码
- **接入诊断**：导入后给出候选数组路径、字段名、建议映射与告警；也支持粘贴 Response JSON 离线分析（不联网、不写配置）
- **多用户**：注册 / 登录 / 会话、邀请码注册、管理员后台；每个账号的数据源、Cookie、推送、AI、课表快照与日志完全隔离
- **App 化预埋**：`POST /api/ingest` 数据注入、可插拔模型服务（自定义请求头 / 模型探测 / 连接测试）、本地 token 鉴权与 CORS
- **定时同步**：默认每天 12:00（Asia/Shanghai，可在设置中改），拉取全量课表并与上次快照做 diff（新增 / 取消 / 教室教师调整 / 周次调整）
- **推送**：Bark（iOS）与 SMTP 邮件双通道；同步后推送「课表变更 + 明日课表预览」；全部发送结果留痕可查
- **AI 助手**：OpenAI 兼容接口（通义千问 / DeepSeek / Ollama 等），自动注入当前教学周、本周课表与待考考试上下文，可回答「明天第一节课在哪」「下一场考试在哪个教室」这类问题
- **手动改课表**：周视图 →「编辑课表」可添加、修改、隐藏课程；改动叠加在同步结果上，不会被下次同步覆盖，可一键恢复自动课表
- **Web 界面**：今日课表 / 周视图（单双周、周次范围过滤）/ 考试安排 / AI 对话 / 同步与推送日志 / 可视化设置

## 快速开始（本地）

```bash
./run.sh            # 默认端口 8300，首次自动建 venv 装依赖
# 或指定端口：./run.sh 9000
```

打开 http://127.0.0.1:8300 。首次启动会自动同步一次演示课表，可直接体验全部界面功能。

macOS 下也可以直接**双击 `start.command`**：会自动起服务并打开浏览器；保持弹出的终端窗口开着即可，关掉窗口服务就停。这样不依赖任何 IDE / 会话托管，避免「页面打不开」。

> 本地 Web 服务不是常驻进程：无论是 `./run.sh` 还是 `start.command`，都需要那个终端窗口一直开着。若浏览器提示连接被拒绝，先确认服务进程还在。

## 部署到 VPS（Docker）

```bash
docker compose up -d --build
```

数据（配置 + SQLite）持久化在 `./data`。建议用 nginx 反代并加访问控制（Basic Auth 或仅内网/ tailscale 访问），**不要裸奔暴露公网**——配置里含教务密码与 API Key。

nginx 反代示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:8300;
    proxy_set_header Host $host;
    proxy_read_timeout 120s;   # AI 回答可能较慢
}
```

不用 Docker 也可以：`python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`，然后用 systemd 跑 `.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8300`。

## 接入真实课表

### 方式一：一键登录门户（推荐，无需抓包）

**准备**：本机装有 Google Chrome，并安装可选依赖（不下载 Chromium，直接调用本机 Chrome）：

```bash
.venv/bin/pip install playwright
```

1. 设置 → 接入方式选「青岛理工门户」→ 点「一键登录门户（推荐）」。
2. 在弹出的 Chrome 窗口里按学校官方页面正常登录（微信扫码 / 短信 / 账号密码 + 验证码都支持）。
3. 程序监听登录后的 JSON 响应，自动找出课表接口、取会话 Cookie、写回配置并立即同步一次；页面实时显示进度与结果。
4. 浏览器 profile 存在 `data/browser_profile/`（已加入 `.gitignore`），下次通常免登录；Cookie 过期再点一次即可。

**为什么不让程序替你输密码**：学校 SSO 登录页是纯 SPA（1.2 MB 打包 JS），密码用页面下发的 RSA 公钥加密，带 `lt` / `execution` / `mfaCode` 等一次性令牌，默认登录方式是微信扫码，异常还会触发图形验证码；登录完还要走 OAuth 换 code 才能建立门户会话。复刻这条链路既脆弱，又要保存全校统一身份密码，还得对抗验证码 / MFA——所以改由真实浏览器完成登录，程序只接管登录之后的会话。

**实测接口**：门户课表来自 `portal/api/v2/datacenter/get/xskb?XN=…&XQ=…`，数组路径 `results.data.Rows`，字段为全大写 `KCMC / XQJ / KSJC / JSJC / SKDD / SKZC`。校历接口 `get/xlxx` 返回学期起止（2026-2027-1：2026-08-31 至 2027-01-17），已据此校正默认开学日期。助手的字段映射大小写无关，并且会过滤 `/api/v2/app?type=app|ziyuan` 这类「应用 / 资源」列表——它们条目更多但不是课表，早期版本曾误把 45 条应用当成 45 门课，现已按「核心课表字段组合 + URL 语义」挑选。

**限制**：需要图形界面桌面，本机 macOS / Windows 可用；VPS / Docker 无桌面环境请用方式二。若门户返回的是「按日期的日程事件流」而非每周循环课表，会明确提示需要事件适配器，不会把配置写成不可用状态。接口 URL 写死了学年学期（`XN` / `XQ`），**换学期请重新点一次一键登录**或手动改地址，否则拉到的还是旧学期课表。

### 方式二：融合门户（手动 cURL 导入）

学校统一身份认证入口 `sso.qut.edu.cn/sso/login?...` 是 **OAuth 登录页，不是课表接口**，直接填进「课表 API 地址」拿不到数据。真实数据来自登录之后课表 / 日程页发出的 XHR 请求。

1. 浏览器登录门户，进入课表 / 日程页（如 `portal.qut.edu.cn/portal/event`）。
2. F12 → Network → 筛选 **Fetch/XHR** → 刷新页面 → 找 Response 是课程 JSON 的那个请求（不是页面 HTML、不是登录请求）。
3. 右键该请求 → Copy → **Copy as cURL**，粘到「设置 → 接入方式选『青岛理工门户』→ 导入并试拉取」。导入会自动配置接口地址、请求头、课程数组路径与字段映射，并立即试拉一次。
4. 导入结果带「响应诊断」：候选数组路径、字段名、建议映射和告警。若课程数为 0，切到该请求的 **Response** 全选复制 JSON，粘到「离线分析响应」——这一步不联网、不写配置。

**注意**

- cURL 含登录 Cookie，**只粘到本地设置页，不要发到聊天或群聊**。需要协助时，把导入结果里「响应预览」（不含 Cookie）复制出来即可。
- Cookie 会过期；过期时同步日志明确报错并推送告警，重新登录门户再导入一次 cURL 即可。
- 若接口 URL 里写死 `week=9` 之类的周次 / 日期参数，每日同步会一直拿同一周的数据，导入结果会提示，尽量改抓不带周次参数的接口。
- 门户若返回的是「按日期的日程事件流」而非每周循环课表，诊断会标记为 `日程事件流`。当前数据模型只表达周期性课程，一次性停课 / 改教室需要单独的事件适配器。

### 方式三：正方教务（学校教务平台为 jwglxt 架构）

设置 → 接入方式选「正方教务系统」，填学号密码，点「测试正方登录」可直接验证是否连通。学期只需选第一学期（`3`，秋季）或第二学期（`12`，春季）。青岛理工 `jxgl.qut.edu.cn` 的登录页使用 RSA 加密密码 + csrftoken，适配器已按真实页面实现（纯 Python RSA，无需额外依赖），并用真实账号验证过课表与考试接口；周次支持 `第15周`、`1-15周(单)`、`1-3周(单),4-8周(双),9周` 等教务原始写法。

连续输错 3 次会要求验证码（学校策略），此时等几分钟再试，或改用 **Cookie 模式**：

1. 浏览器登录 `jxgl.qut.edu.cn/jwglxt`，打开开发者工具 → Network
2. 刷新课表页，复制任意请求头中的 `Cookie` 值粘贴到设置
3. 保存并立即同步

> 正方适配器实测可用：课表 `kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151` → `kbList`，考试 `kwgl/kscx_cxXsksxxIndex.html?doType=query&gnmkdm=N358105` → `items`（含考场 `cdmc`、座号 `zwh`、考试时间 `kssj`）。考试接口不可用时只保留课表同步，不影响其他功能。Cookie 会过期，过期后同步日志会报错，重新粘贴即可。

### 方式四：学校个人课表 API（如果你已有接口）

设置 → 接入方式选「通用 HTTP JSON 接口」，填 API 地址、请求头（如 App 抓包得到的 token）、课程数组的点路径（如 `data.courses`）。
字段映射默认 `name/teacher/room/day/start/end/weeks`；接口字段名不同时编辑 `data/config.json` 的 `provider.http_mapping`。
`weeks` 支持数组或「1-16周」「2-16(单)」这类字符串。

### 学期参数

- **开学日期**：第 1 周周一的日期，按校历修改（默认 2026-08-31，来自门户校历接口 `get/xlxx`，2026-2027-1 学期为 2026-08-31 至 2027-01-17）
- **节次时间**：默认按学校实际 10 节 × 50 分钟（08:00–08:50、09:00–09:50、10:10–11:00、11:10–12:00、14:00–14:50、15:00–15:50、16:10–17:00、17:10–18:00、19:00–19:50、20:00–20:50）；不符时在 `data/config.json` 的 `section_times` / `section_ends` 覆盖

### 手动调整课表

周视图 →「编辑课表」：

- **添加课程**：名称、星期、节次、周次、教室、教师、备注；周次支持 `1-16`、`1-15(单)`、`3,5,7`
- **修改 / 隐藏**：临时换教室、换老师，或停开的课先隐藏
- 调整单独保存在账号配置里，叠加在同步结果上：下次同步只更新原始快照，不会覆盖手动改动；「恢复自动课表」可一键还原
- 周视图、今日、AI 上下文和明日推送都使用调整后的课表；变更检测仍对比原始同步结果，不会把手工改动误报成教务调课

## 多用户与账号

每个账号的课表数据源、门户 Cookie、推送配置、AI Key、课表快照和日志**完全隔离**，A 看不到 B 的课表。

### 首次使用

打开页面会看到注册表单。**第一个注册的账号自动成为管理员**，并继承升级前 `data/config.json` 的配置和已有课表（旧 `snapshot` 表在启动时自动迁移为按用户存储，无需手工操作）。之后注册必须凭邀请码。

### 注册与登录

- 管理员在「设置 → 账号与邀请码」点「生成邀请码」发给同学，邀请码一次性、7 天有效。
- 注册填用户名、密码（≥8 位）、可选显示名与学号、邀请码。
- 密码用 PBKDF2-HMAC-SHA256 + 随机 salt 存库，不存明文；会话为 HttpOnly Cookie（7 天），登录失败按 IP 每分钟限 5 次。
- 相关接口：`GET /api/auth/status`、`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET|POST /api/auth/invites`、`GET /api/auth/users`。

### 隔离怎么实现

`app/user_context.py` 用 `ContextVar` 绑定当前请求用户；`config.load_config()` 和 `db` 的快照 / 日志函数自动按用户读写，所以现有二十多个业务接口不用逐个改。定时任务逐个用户切换上下文后同步；一键登录窗口归属发起用户，写回的配置也只落到该账号。

### 升级与部署注意

- 除 `/api/health`、注册、登录、登录状态外，所有 `/api/*` 都要有效会话；`security.enabled` 开启时跨源调用还需本地 token。旧的「只靠 Origin 判断」绕过已修复。
- 服务器无桌面，一键登录用不了：每个用户在自己的设置页粘贴 cURL 接入，或由管理员把抓好的配置写到对应账号。
- **公网多用户务必配 HTTPS**，否则会话 Cookie 是明文传输；8300 仍不要直接暴露。
- 升级后需要重新打包 / 重建镜像并重启服务，旧数据会自动迁移。

## 后期封装成 App 的预埋

登录方式与数据处理已经解耦，换 App 外壳时核心逻辑不用改。

### 数据入口：POST /api/ingest

原生登录容器（App 内 WebView / 浏览器扩展 / 桌面浏览器脚本）在登录态里直接 fetch 课表接口，把 **JSON 数据**传进来即可，Cookie 不需要也不应该导出：

```bash
curl -X POST http://127.0.0.1:8300/api/ingest \
  -H 'Content-Type: application/json' \
  -H 'X-Local-Token: <token>' \
  -d '{"payload": {"code":200,"data":{"courses":[]}}, "push": false, "source": "app"}'
```

| 字段 | 说明 |
|---|---|
| `payload` | 课表接口原始响应（必填） |
| `list_path` / `mapping` | 可选；缺省时自动猜测，猜不出会返回结构诊断 |
| `push` | 是否同步后推送变更，默认 `false` |
| `source` | 快照来源标记 |

后端自动完成解析 → 与上次快照 diff → 保存 → 更新 AI 上下文（可选推送）。若收到的是「按日期的日程事件流」，会明确提示需要事件适配器，不会写入错误数据。

### 为什么不能调系统默认浏览器

系统浏览器的会话 Cookie 在它自己的沙盒里，App 读不到（`HttpOnly` 连 JS 也读不到）；学校这套 OAuth 的 `redirect_uri` 写死门户回调、`client_id` 属于门户，无法注册自有回调 scheme 把 code 送回 App。正解是 **App 内 WebView 登录后在该上下文里直接 fetch，只传数据不传会话**。学校默认微信扫码在内嵌 WebView 里可能受限，需保留账号密码 / 短信兜底。

### 模型服务可插拔

设置页可填任意 OpenAI 兼容服务的「接口地址 / 模型 / API Key」，另有：自定义请求头（JSON，可覆盖 `Authorization` 适配自建网关）、「探测可用模型」调用 `/models`、「测试连接」发极短请求验证配置，以及通义千问 / DeepSeek / 本地 Ollama 三个预设。对应接口 `GET /api/ai/models`、`POST /api/ai/test`。

### 本地 token 鉴权与 CORS

设置 → 「安全 · App 接入」开启后：同源页面（浏览器直接访问）不受影响；跨源调用需带 `Authorization: Bearer <token>` 或 `X-Local-Token`。默认允许 `tauri://localhost`、`capacitor://localhost`、`app://*` 与本机 `localhost/127.0.0.1` 任意端口，可追加来源。**默认关闭**，开启前行为与 v1.0 一致。

桌面 App 可直接复用现有 Python 后端 + WebView 壳（含一键登录）；移动 App 跑不了 uvicorn，需要把后端放服务器（App 用 `/api/ingest` 上传数据）或用 Swift/Kotlin 重写核心。
